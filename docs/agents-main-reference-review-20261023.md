## 当前实现与参考实现的关键差距

当前engine.py:110主要按问题词与标题的交集数量排序，再按发布日期；参考BM25分块在标题与正文段落上计算词频/逆文档频率，保留原文offset。它能帮助找到标题不显眼而正文含关键事实的文章。仍需核对完整上下文、指代、冲突和事件五要素；从正文中挑到相关片段不等于片段支持目标事件。

检索索引允许预先读取、分块或编码正文时，必须把离线建索引/嵌入成本与运行期模型阅读成本分开记录。不能全文索引后声称系统完全未接触正文，更不能将全部正文的方向性预判免费用于调度。模型可见的只有本轮预算允许读取的内容。

## 不能直接照搬的细节

1. 已实际复现：retrieval_experiments的eligible_documents对缺失first_seen_date/version_observation_date取空字符串，记录可能通过门控。专利端应继续拒绝缺失时间，不能因迁移降低标准。
2. 旧BM25搬运包README明确说明未新增scraped_at门控，允许跨事件语料；当前专利引擎按event_id隔离。不能直接照搬这套候选范围或宣称其PIT无泄漏。
3. retrieval_common.count_tokens缺少tiktoken时退化为字符估计；不能用于真实token账单或严格模型预算验证。另一个BM25搬运包使用真实Qwen tokenizer并要求不可用时停止，两套实现需要区分。
4. BM25停用词包含not/no，且检索片段可能省略上下文。因此排序只用于召回，否定、冲突、时间约束须在原文证据校验中保留，不能把检索token用于语义判决。
5. pack_evidence遇到第一个超预算块即break，可能留下可用空间；这是一种预注册选择策略，不是通用的最佳装包方式。若改为跳过大块继续选择，应独立标记策略并做同预算比较。
6. 来源上限、5-token shingle近重复阈值只用于候选多样性，不能替代专利独立当量。RRF分数也不是事态概率。
7. 论文评估器使用配对成功实例，需同时补报失败率及全体尝试数，避免靠丢弃难例制造提升。本文没有把目录中的既有结果数值当作当前专利的有效性证据。

## 建议下一实施单元与验收

先做一轮有边界的改进：预算可执行性预检和无效查询诊断 + 在专利允许范围内的BM25候选排序/段落定位 + 阅读/准入链路核对。明确这是工程检索层改进；专利主公式和判据保留，参数配置必须满足[0201]最小检索可执行性。

随后冻结相同开发事件，建立2×2对照：原/改进候选检索 × 固定窗口/专利动态窗口。统一可执行成本口径与模型版本；参数只在开发数据确定。三策略中的基础动态可另列补充对照。先验收有效新读取、无效查询消耗、正确任务匹配、独立事实覆盖、损失观测完整度及回收后的证据留存。已有机器标注只能说明对这些标注的覆盖，不能直接当语义真值；未经验证的新闻不能叫“有效事实”。

如参考全可见语料用于离线诊断，应单独标记为诊断上界，不能把未读文档的支持度、标签或未来版本反馈给调度器。效果门槛未达到时定位漏斗损失，不扩大调用。最后在语义开发未使用、具有可信结算标签的新事件上，才验收Brier/Log loss及实际调用成本。
