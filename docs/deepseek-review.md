# DeepSeek 自动语义流程独立复核

复核日期：2026-10-22。范围为客户端、机器标注验证、自动抽样与三方案回放、保存产物及历史代码归档。本复核不调用真实 API、不读取凭据、不重建原始数据索引、不修改已保存实验。

## 结论与当前发现

工程链路已跑通，但首批真实语义输出存在价格信号混入，不能将其称为排除了市场价格的新闻方向性证据。`artifacts/deepseek-20260515` 保存的 50 条标注中，6 条非零支持均属于市场 `958443`，全部通过新闻中的预测市场赔率或赔率变化判断方向。其余 44 条支持为零；15 次最终预测均为 0.5 / 0.5。这不是预测质量验证。

可复现例：`runs/958443/machine-annotations.json` 中文档 `142a014d6686494f81a0e5c9aab6620c6913db82071c07a96c4e6bf30aa41f2e` 的引用为 “Odds for the regime falling by June 30 rose to 13.5% YES, up from 12% yesterday.”，支持向量为 `[1,-1]`，解释明确将赔率上升视为支持 Yes 的依据。系统提示禁止使用市场价格，但当价格出现在文章正文时，仅靠结构及逐字引用校验不能落实该要求。此发现已提交主执行代理；原始结果应保留，修订产物应另存并明确价格信号排除规则。

## 已修复并复验的问题

1. 持久化机器标注曾允许删除 `excerpt`，继而把引用替换成全文中未送给模型的段落。现在创建和重验都要求非空模型名及原文前缀 excerpt，且引用必须在该 excerpt 中。新增回归测试覆盖缺失模型、缺失 excerpt 和越界引用。
2. 产物验证器起初没有 `semantic_pipeline` 根清单分支。补充分支后，又修正了完整正文与引擎投影字段比较以及时间字符串格式差异。完整成功、部分失败、全部失败三类合成结果均通过新的根清单验证。

## 验证证据

- `python.exe -B test.py`：91 项测试通过。
- `python.exe -B scripts/verify_artifacts.py`：46 份运行产物通过，即原有 31 份加本次 15 份；5 个旧试点任务和 5 个准备任务通过，33 次代码校验使用原始内容哈希归档。
- 真实首批汇总：5 个不同事件，1,563 篇可用正文中预先抽样 50 篇，50 次返回和结构校验成功；返回模型为 `deepseek-flash`，实际记录 76,589 tokens，其中输入 70,835、输出 5,754，无本地缓存命中。
- 三方案使用相同冻结有效输入和标注哈希；所有任务预测完成后才读取代理标签；官方结算未核验，`verified_brier` 保持空值。
- 请求限定官方 HTTPS 端点并拒绝重定向；错误消息不保存远端响应、认证头或异常参数；缓存排除推理内容与认证信息。
- 输出和缓存拒绝进入原始数据目录，输出必须新建或为空；索引通过 SQLite 只读连接访问。时间筛选同时要求发布时间和观测时间不晚于 cutoff。
- 模型请求、验证失败、缓存 token 与本次非缓存 token 分开统计；全部验证失败时不生成预测，不把失败补成零支持成功记录。检索调度成本仍为模拟单位，不能与真实 API token 混算为节省。

## 适用边界

逐字引用及哈希绑定只能证明来源与结构，不能独立证明模型的事实解释、事件周期或方向判断正确。显式 ISO 日期和时刻有机械检查，自然语言时间仍依赖模型。历史回测还可能受模型未来知识影响。当前候选状态依据截止时元数据，语义期限未独立核验；50 篇预先抽样不代表全量正文。原有 31 份产物通过哈希校验保留，未被新实验覆盖。

## v2 修复复核

`evidence-semantics-v2` 已在提示词中明确要求排除新闻引用的预测市场赔率、隐含概率、YES/NO 合约价格及其变化，并在创建及重验时拒绝引用或解释包含这些信号的非零支持。普通现实指标和百分比不因数字本身被排除。对原始真实结果进行只读回查：6 条既有非零价格信号全部被新检测器命中；当前运行时拒绝全部 50 条旧 v1 标注，不能靠旧缓存或旧标注绕过新政策。

历史验证器仅在 SHA256 确认后载入当次归档验证模块，并显式列出按旧政策验证的实验；这证明历史文件与当时规则一致，不表示通过新政策。原始 v1 结果保持不变。

本复核的最终测试重跑曾因 C 盘可用空间降至 0 而出现 `OSError: [Errno 28] No space left on device`，不能将那次 94 项测试记为通过；错误发生在临时数据写入和报告保存，已告知主执行代理并停止写入密集的测试。后续只读检查观察到空间恢复。v2 最终真实产物须在根 manifest 完整并重新通过校验后才能标为完成。

新规则是保守的文本检测器，可能排除含有普通用法 “odds” 的有效事实，也不能保证捕获所有未使用这些关键词的价格信号。它修复了本次观察到的具体问题，不构成语义真实性或完全无泄漏的证明。

## 主执行代理最终复验与处置

v2 已加入赔率衍生非零支持拒绝规则及提示词版本隔离，当前引擎拒绝 v1 标注；旧版产物仅由哈希校验后的历史验证器复核完整性。此前发现的 6 条非零价格支持均被该规则识别。修正版真实 50 条标注全部为零支持，50/50 校验通过、15 次运行完成。该门槛是保守启发式，不能证明排除所有改写形式。

复核代理后续测试遇到 C 盘耗尽，未将失败重跑记为通过。主执行代理迁移全部项目数据到 D 盘并设置 D 盘测试临时目录后，独立执行 94 项完整测试通过、61 份运行完整性检查通过、50 次缓存回放与原结果一致，额外 API 请求为零。最终代码与产物位于 D 盘根项目，历史开发副本只供追溯。
