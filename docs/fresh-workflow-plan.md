# 新事件工作流与独立评价
用户已授权：新事件选择 → 截止时间设置 → 模型抽取 → 运行，随后独立评价。
沿用本地标准库服务、原生前端、共享单任务队列，D盘文件，密钥仅进程环境。
1. 新事件服务：状态/归档日期、候选筛选、选定市场冻结输入；预览不调用模型。排除历史预测事件及相同URL/正文，按已有覆盖门槛筛选。
2. 共享JobManager新增semantic模式：只提交服务生成的preview_id；冻结清单验证；单子进程抽取与三方案；真实已完成文档进度、取消、部分失败、重启不自动付费重跑；幂等键防重复提交。运行时才检查凭据。
3. 前端新事件面板：UTC明确日期、预览、选择、样本上限（12–40）、配置、启动、进度、失败/取消、回放；不输入密钥。后端只返回配置是否存在。
4. semantic_pipeline增加可选observer与matching_policy（默认仍typed_v3），逐篇缓存/抽取记录立即保存；不改变旧调用结果。前端流程显式typed_v4。
5. 全面测试后冻结10个未曝光事件×最多20文档，截止2026-08-28T23:59:59Z，固定seed web-fresh-v1（采用实际网页预览，模型调用前冻结）。若不足保持实际分母，不降低覆盖门槛。所有预测冻结再读取官方标签，以现有terminal-winner协议评价；冻结以后不按结果改规则。
6. 源码归档、全量回归、工件验证、浏览器验收、更新交付清单。

预检：前端只写web与tests/test_fresh_viewmodel.mjs；主代理写后端与Python测试；API契约在frontend brief固定；观测新增可选参数保持旧调用输出。非Git项目按用户指定直接D盘开发，不创建checkout。
