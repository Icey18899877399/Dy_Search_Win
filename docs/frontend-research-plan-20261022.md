## 3. 三条实现路线
A. 增强离线 HTML：最接近原计划，适合回放与导出；无法单靠 file:// 页面可靠启动本地 Python 任务。
B. 本地操作工作台（推荐）：Python 标准库本地服务 + 模块化原生 JavaScript + 本地打包的 ECharts。
   保留 Python 零第三方运行依赖；浏览器侧新增一个图表依赖。使用 shadcn 的布局思路，不直接复制其 React 组件。
   不要求用户运行 Node 构建工具。静态图表库固定版本并记录许可证、来源及校验值，无 CDN。
C. React + TypeScript + Vite + ECharts：适合更长期的复杂交互；增加构建链和依赖维护，超出最初轻量交付约定。
   当前功能规模优先 B，后续是否迁移由实际交互复杂度决定。

运行入口拟为 run_web.py，仅绑定本机 127.0.0.1，提供静态页面与 JSON 接口。
新增服务读取原引擎/流水线，前端不重新实现概率、准入和窗口决策。
离线回放不调用模型；真实抽取显式选择运行模式，密钥仅保留在服务进程环境。

## 4. 初版页面与主路径
主路径：选择任务 → 配置 → 启动 → 查看运行状态 → 回放窗口与证据 → 三方案比较 → 导出。
主导航控制为四项：
1. 任务中心：历史/新任务、事件筛选、截止时间、三种策略、预算和窗口配置。
2. 调度工作台：初版核心，展示某任务某轮次的窗口、证据、来源、概率和预算。
3. 实验对比：固定/基础/增强共享输入的曲线和结果、成本口径、可评分样本分母。
4. 运行记录：状态、错误、模型版本、输入指纹、导出文件和原有离线报告。

工作台布局草图：
    顶栏：事件名称｜截止时刻｜策略｜任务状态｜导出
    侧栏：任务 / 调度 / 对比 / 记录
    主区：概率、有效证据、模拟预算、当前轮次
          [横向时间轴：历史范围｜过渡带｜主窗口｜固定截止线]
          [证据点：支持 / 反对 / 中性；点击联动右侧详情]
          [概率与损失曲线] [预算曲线与来源状态时间轴]
          [上一轮 / 播放回放 / 下一轮 / 轮次滑块]
    右栏：证据标题、原文、五要素逐项匹配、支持方向、准入原因

横向时间轴表示新闻/事实相关时间，轮次由独立滑块控制；轮次模拟时钟和实际任务耗时不混用。
边界移动展示 boundary_before 与 boundary_after；概率必须标明对应引擎的计量阶段。
播放按钮只回放已有数据，不暗示算法正在实时运行。
用户不能在回放图上拖动边界改写原实验；参数变化创建新运行。

## 6. 数据复用与必须补齐的接口
可复用：rounds 中的边界、概率、loss_ratio、net_gain、cooldown_remaining、
source_states、source_budgets、budget、retrieved_ids、recovered_ids、window_ids；
evidence 中的要素、出处、支持向量、匹配轨迹（若该版本提供）。
注意：当前导出的 weight 是最终轮口径，不能直接画成所有历史轮权重。
逐轮权重需调用同版本后端计量或在新运行中记录；老数据缺失应显示未记录。
标题、全文与未读取文档来自冻结 inputs；不得用当前原始归档覆盖历史版本。
不同工件版本先做适配和索引，不要求页面直接加载所有 811 份完整结果。

拟新增只读接口：任务列表、运行列表、单运行摘要、轮次、分页证据、已有评价和导出。
拟新增操作接口：创建运行、查询运行进度、请求取消。
配置复用 Config 的校验；拒绝任意命令、外部文件路径和覆盖历史运行。
每次运行独立目录与输入指纹；单任务工作队列，避免重复点击产生重复模型请求。
进度基于已完成文档/阶段/轮次记录；未知总量只显示阶段和计数，不伪造百分比。
任务状态区分 queued/running/completed/partial/failed/cancelled；取消保留已完成缓存和部分结果。
运行时进度采用轮询；前端断开不会终止后台任务，服务重启后将遗留运行标为中断，不自动追加付费调用。
服务校验本机请求来源与运行令牌；密钥不进入浏览器、localStorage、日志或导出。
原文渲染为文本，原文链接仅允许 http/https。

目前未完整记录逐格实际花费、每步精细耗时、所有拒绝原因。新增日志必须为版本化附加观测，不改变计算结果。
改动历史 manifest 引用的源码前先归档；新旧运行对照结果与逐轮输出应一致。
模拟预算、模型 token 用量、已核实账单金额分别呈现；不能相互换算冒充实测。
不同输入/版本的运行可以并列浏览，但不能标成公平的三方案对照。
标签仅供预测完成后的评价页面读取，保持评分协议、分母和排除原因。

## 7. 开发顺序与验收（建议新增 Task 9）
| 阶段 | 可验收交付 | 工作量估计 |
|---|---|---|
| 9A 读取与原型 | 工件适配、任务列表、一个真实任务的窗口/证据联动回放 | 0.5–1 天 |
| 9B 核心可视化 | 来源状态、概率/预算/损失联动、五要素与拒绝原因；补必要观测 | 1–1.5 天 |
| 9C 运行闭环 | 配置校验、启动、阶段进度、取消/失败、记录与导出 | 1–1.5 天 |
| 9D 对比与验收 | 三策略共享输入对比、离线包、浏览器检查和回归 | 0.5–1 天 |

总计约 3–5 个专注工作日，是规划估算，不是自动后台执行或质量提升承诺。
先完成 9A，以真实数据检验信息布局，再推进其余阶段；不先扩大 API 样本量。
语义实体/反向事实匹配作为原 Task 8 的独立剩余项；扩大独立评价仍归 Task 7。
“完整初版”要求前端闭环与当前核心缺陷有明确处理结果；性能优于基线是另一验收目标。

验收清单：
- [ ] 从网页选一个冻结任务、配置并启动，到完成/部分完成/失败状态均可解释。
- [ ] 点击任意已记录轮次，窗口、概率、来源状态和证据一致；缺失字段不补造。
- [ ] 真实零方向样例明确显示中性结果；合成样例单独标记，可用于演示窗口变化。
- [ ] 固定/基础/增强对照校验输入指纹，得分显示协议和分母。
- [ ] 历史工件内容及 manifest 不改写，新增观察记录不改变同输入预测结果。
- [ ] 分页与按需加载，空数据/长中文/长原文/提取失败/不支持题型均有页面状态。
- [ ] 在 1440px 与 1280px 浏览器检查交互、键盘操作和图表溢出。
- [ ] 本地回放断网可用；原离线 HTML 仍可打开和导出。
- [ ] 代码、依赖、缓存、日志、构建输出与测试临时文件全部位于 D 盘项目目录。
