# 阶段十四：整带回收对照、实测观测、独立评价准备

用户已批准顺序：整带回收对照 → 真实标定观测 → 独立评价。D盘原地开发，原数据只读，历史版本与结果保留。

## 预先确定的执行口径

1. 新的 recovery_policy='patent_full_band_v1' 显式开启；旧接口默认行为与阶段十三完整输出一致。整带不足预算时拒绝，不自动退为部分跨度；损失率和非负净收益同时成立才回收，冷却期间不重新估值。归档早端不足名义整带时不冒充完整回收。
2. 两种调度 basic/enhanced 分别做部分带/整带对照；预算轴分别为旧单轮20与按总预算200/24轮派生。fixed作为各预算轴对照。同一18事件、356有效文档、原标注与V6准入。它们都是已用开发数据。
3. 收集真实已有运行日志与当前本地归档查询观测，记录精确出处、响应时延、返回数量、错误、时间和单位；本地查询不当成发布者网络接口，未知配额不补值。不从新闻发表间隔或市场结算时刻推导酝酿期。
4. 独立评价前必须扩大历史暴露排除注册表，包含已准备、已筛查及诊断数据，不能仅排除有result.json的事件。检查是否还存在未暴露候选；参数与样本冻结前不读取其方向性标注/结算标签。
5. 若观测字段或独立候选不足，输出明确门槛与未完成原因，不能以开发回放替代独立评价。独立评价不为凑数量降低窗口覆盖/正文/来源门槛。

- 整带引擎与行为测试：独立实现任务；只修改engine.py/on_demand.py/test_full_band.py。

- 主任务：专利原文复核、180次预定开发对照、核验/报告与评价准备。
- Ruling：常规预算派生作为实验Config独立轴，避免把预算变动与整带机制混为同一效果。
- Ruling：已授权的设计继续实施，不重复要求确认；实测缺项必须保留，独立评价依赖门槛不以时间流逝视为通过。
